# Implementation failures and rejected alternatives

1. **Direct Git push rejected.** `git push -u origin main` could not read a GitHub username from the shell. The connected GitHub account confirmed push permission, so commits were published via the GitHub repository API. The local repository was realigned to the published branch.
2. **Browser launch denied.** Playwright launched `/usr/bin/chromium`, which exited at `process_singleton_posix.cc` because the process socket was not permitted. Chosen response: keep state-interface experiment separately labeled; no browser portability claim. A future browser-capable environment is required for the complete v3 plan.
3. **Separate tool commands could not reach Vite sessions.** Long-running servers started in one shell were unreachable from another tool command. Integration tests and CLI now start, use, and terminate the processes within one command.
4. **Initial-state test assertion was wrong.** The mock writes `.initial.json` only on first injection of a SID, so injecting a modified state changes `current_state`, not `initial_state`. Tests now use fresh SIDs and compare current states; repair uses a new session.
5. **Relative verifier path failed.** A reward path relative to the working directory was duplicated when `subprocess.run` changed `cwd`. Added a failing regression test, then resolved the verifier directory before invocation.
6. **Test run count was wrong.** Initial repeated-trial test expected six clean runs for three tasks times two repeats, omitting the two runtimes. Corrected to twelve after inspecting the design.
7. **One fault was not harmful.** Removing an unchanged, nonqualifying email still yielded full reward in two tasks, so it would inflate the avoided-rollout metric. Probed original rewards and selected the first two qualifying emails instead; all forced counterfactual rewards are below 1.0.
8. **Fixture path symlinks initially pointed too high.** Integration tests skipped on an invalid local shortcut. Corrected local link targets. The reproducible bootstrap creates real directories rather than relying on those links.
9. **Fresh bootstrap exposed a skipped test.** One isolation test used a task ID outside the three downloaded bundles. Switched it to a selected bundle, then noticed its initial label list was already empty, making the changed-state assertion false. The test now changes the email folder and runs against the fresh bootstrap without skips.

10. **Browser test exposed upstream archive mismatch.** All six project emails were labeled and archived through visible controls on both runtimes, but the original reward remained 0.1. Source inspection showed the UI writes `folder: 'all-mail'` while `reward.py` requires `folder: 'archive'`. This is a benchmark/app compatibility failure; we preserved the failing reference and tested a one-line versioned patch in a third independent app process. The patched task earned full reward in three repeats.

11. **A repaired runtime entered the unmodified test set.** A first CI retry mistakenly iterated port 5175 in the unmodified task loop; its 1.0 project reward correctly violated the expected 0.1. Restricted the baseline loop to ports 5173 and 5174 and tested 5175 separately.
12. **Pristine negatives hid false positives.** The initial 0% false-positive rate used only exact expected states. Added unrelated-label controls; all nine were blocked despite full reward in forced trials, raising the measured rate to 9/27 (33.3%) for this sample.
13. **Local bootstrap shortcut confused npm.** A second bootstrap run on the symlinked local fixture tree reported a lockfile mismatch; a clean checkout with real directories bootstrapped and ran eleven tests successfully. Repaired runtime was prepared directly in the local fixture. CI also bootstrapped successfully from a clean checkout.

Rejected scope: Kafka, Kubernetes, a new mock app, dashboard, and model agent would add complexity without strengthening the portability experiment. An unpinned hosted demo endpoint would undermine repeatability. Running upstream setup scripts directly would spawn a browser and reuse shared `/tmp` SID state. Treating privileged `/post` mutations as CUA actions would overstate the findings.
